# Fresh 0.2.0 Storage Progress

Fresh 0.2.0 moves every persistence operation behind a pluggable storage boundary while preserving the existing zero-configuration LittleFS API and persisted database formats.

## Software implementation status

**Complete**

Fresh now supports the same database, backup, restore, and garbage-collection engine on:

- Fresh-managed LittleFS
- Fresh-managed SD over SPI
- Fresh-managed SDMMC where the target supports it
- Fresh-owned custom storage backends
- Caller-owned, already-mounted custom storage backends
- Custom non-VFS file implementations

The database and application-managed backup archives use the same selected storage instance. Cross-filesystem migration and automatic fallback remain intentionally outside the 0.2.0 scope.

The software implementation is complete. Physical transport qualification remains a release-validation activity rather than unfinished storage architecture work.

## Explicitly deferred beyond 0.2.0

- Automatic migration between filesystems
- Simultaneous database storage across multiple filesystems
- Automatic SD-to-LittleFS fallback
- SD card hot-swap recovery
- Automatic remount after card replacement
- Bundled network, USB, or remote storage transports
- Automatic backup archive copying between filesystems

Custom network, USB, encrypted, or other storage remains possible through `FreshStorage`; Fresh 0.2.0 simply does not bundle those transports.
