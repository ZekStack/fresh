# Fresh 0.2.0 storage progress

## Completed architecture

- [x] Move storage selection out of `FreshConfig`.
- [x] Make explicit backends Fresh-owned.
- [x] Keep default LittleFS initialization as a convenience overload.
- [x] Add `FreshInitResult` alias.
- [x] Add `db.storage()` application-file facade.
- [x] Add complete-file read/write helpers.
- [x] Add recursive directory creation, listing, removal, size, and rename operations.
- [x] Protect the configured Fresh database root.
- [x] Track internal and application file handles.
- [x] Return `FreshStatus::Busy` while application files remain open.
- [x] Add destructive whole-volume `Fresh::format()` lifecycle support.
- [x] Invalidate retained file and model handles during formatting.
- [x] Rebuild an empty durable database after successful formatting.
- [x] Remove `withStorage()` and raw backend pointers.
- [x] Remove borrowed-storage initialization.
- [x] Remove storage factory and reference-wrapper code.
- [x] Remove Arduino filesystem bridges and production singleton dependencies.

## Built-in backends

- [x] ESP-IDF LittleFS.
- [x] ESP-IDF SDSPI.
- [x] ESP-IDF SDMMC.
- [x] Dedicated ESP-IDF eMMC backend with 1/4/8-bit bus configuration.
- [x] Whole-volume formatting for LittleFS, SDSPI, SDMMC, and eMMC.
- [x] Custom non-VFS backend support.
- [x] Optional custom-backend formatting contract.

## Automated validation

- [x] Source-boundary audit.
- [x] Metadata and Arduino lint.
- [x] Arduino CLI build matrix for ESP32, ESP32-C3, ESP32-S3, and ESP32-P4.
- [x] PIOArduino example build matrix for the same targets.
- [x] Hardening build with failure injection.
- [x] Application-file lifecycle regression.
- [x] Storage-format lifecycle and failure regression.
- [x] Short-write/read/sync/close/exists failure regression.
- [x] Custom-backend persistence across backend object replacement.

## Physical qualification required

- [ ] Managed SDSPI on representative cards.
- [ ] External/shared SDSPI ownership.
- [ ] Waveshare ESP32-P4-Module-DEV-KIT onboard SDMMC.
- [ ] One-bit and four-bit SDMMC wiring.
- [ ] Four-bit and eight-bit eMMC wiring.
- [ ] Whole-volume format and remount on representative LittleFS, SD, and eMMC media.
- [ ] Missing card/device behavior.
- [ ] Full filesystem behavior.
- [ ] Card removal during read, journal append, snapshot, application-file writes, and format.
- [ ] Power loss during journal, durable-slot, backup, rename, and format operations.
- [ ] Board-specific power/LDO/reset sequencing.

## Deferred

- Automatic removable-media remount.
- Hot-swap recovery without application restart.
- Multiple simultaneously mounted Fresh-managed volumes.
- Database and application files on independently selected backends.
