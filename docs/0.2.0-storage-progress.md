# Fresh 0.2.0 Storage Progress

This document tracks the implementation of the pluggable, Fresh-managed storage architecture planned for Fresh 0.2.0.

## Target

Fresh 0.2.0 will allow applications to select a built-in storage backend through `FreshConfig`. Fresh will create, mount, own, unmount, and destroy the selected backend.

Initial supported backends:

- LittleFS
- SD over SPI using ESP-IDF
- SD over SDMMC using ESP-IDF where supported

The database and application-managed backup archives will use the same selected filesystem. Cross-filesystem migration and copying are outside the 0.2.0 scope.

## Explicitly deferred beyond 0.2.0

- Automatic migration between filesystems
- Simultaneous database storage across multiple filesystems
- Automatic SD-to-LittleFS fallback
- SD card hot-swap recovery
- Automatic remount after card replacement
- Network, USB, or remote storage backends
- Backup archive copying between filesystems

## Current implementation notes

- `FreshStorageType`, LittleFS, SDSPI, SDMMC, and SPI ownership configuration types now exist in `src/FreshStorage.h`.
- The abstract backend contract exposes storage identity, state, capacity, and Fresh-controlled mount lifecycle methods.
- `FreshLittleFSStorage` currently wraps the Arduino LittleFS singleton as a transitional compatibility backend.
- The compatibility backend is not yet connected to `FreshConfig` or the persistence engine.
- The existing persistence engine still calls the Arduino `LittleFS` singleton directly.
- Storage replacement must be performed incrementally without weakening journal, snapshot, manifest, restore, or garbage-collection durability.
- The alternate manifest slot remains the durable restore commit boundary.
- Storage formatting must always be explicitly enabled. SD formatting remains disabled by default.

## Next development step

Connect the storage types to `FreshConfig`, make Fresh own the selected backend, and route LittleFS initialization, storage information, rollback, and deinitialization through `FreshLittleFSStorage`. After that, introduce the VFS-backed `FreshFile` layer before migrating persistence operations.
